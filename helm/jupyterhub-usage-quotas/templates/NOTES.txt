### Post-installation checklist

  - Register the service with JupyterHub. Add this to the config of the
    jupyterhub chart (z2jh) in the "{{ .Release.Namespace }}" namespace, then
    upgrade that release:

      hub:
        services:
          {{ $serviceName }}:
            url: http://{{ $fullname }}:{{ .Values.service.port }}
            display: true
            oauth_no_confirm: true
        loadRoles:
          {{ $serviceName }}-service:
            scopes:
              - read:users
              - list:services
              - read:services
            services:
              - {{ $serviceName }}
          user:
            scopes:
              - self
              - access:services!service={{ $serviceName }}

    The "user" role replaces the default user role of JupyterHub. If your
    config already has a "user" role, add the scope to it.
    {{- if .Values.jupyterhub.apiToken.value }}

    Also set hub.services.{{ $serviceName }}.apiToken to the same value as
    jupyterhub.apiToken.value in this chart.
    {{- else }}

    z2jh then creates the API token for the service in the
    "{{ .Values.jupyterhub.apiToken.existingSecret.name }}" Secret. The pod of this chart stays in the
    CreateContainerConfigError state until that token exists.
    {{- end }}

  - Verify that the created Pods enter a Running state:

      kubectl --namespace={{ .Release.Namespace }} get pod -l app.kubernetes.io/instance={{ .Release.Name }}

    If a pod is stuck with a Pending or ContainerCreating status, diagnose with:

      kubectl --namespace={{ .Release.Namespace }} describe pod <name of pod>

    If a pod keeps restarting, diagnose with:

      kubectl --namespace={{ .Release.Namespace }} logs --previous <name of pod>
